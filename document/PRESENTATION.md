## 2. 기술적 도전 및 트러블슈팅

### 소프트웨어 설계와 아키텍처 패턴
- **문제:** 프로젝트 초기에 어떤 아키텍처(레이어드, 헥사고날, 클린)를 선택할지 고민
- **접근:** Controller → UseCase → Domain → Port → Adapter 구조로 계층 분리, 의존성 방향성 명확히 함
- **해결:** Ports & Adapters 패턴 적용으로 도메인과 외부 의존성 분리, 테스트와 확장성 확보

### 동시성 제어 및 안정성 확보
- **문제:** 다중 스레드 쿠폰 발급 시 Over-Issue 발생
- **해결:** Redis Lua 스크립트 + ZSET Gatekeeper + TTL 관리 → 안정적 발급 보장

### 이벤트 유실 및 데이터 정합성
- **문제:** Kafka Consumer 다운 시 메시지 유실
- **해결:** Outbox 테이블 + Polling Publisher → 메시지 재처리 가능
    - Exactly-Once 설정으로 중복 처리 방지

### 성능 병목 및 DB 풀 고갈
- **문제:** k6 부하 테스트에서 p95 59.99s, 에러율 7.9% → 커넥션 풀 대기
- **해결:**
    - Kafka 비동기화로 주문/결제 후속 로직 분리 → 응답 시간 단축
    - HikariCP 풀 확장 + 모니터링 지표 확인 (DB/Redis Ops/sec, Kafka Lag)

### 테스트 환경 안정화
- **문제:** Testcontainers Kafka 기동 지연, CI 환경 불안정
- **해결:** KRaft 모드 컨테이너 적용, bootstrap-server 주입 → 테스트 성공률 100% 확보

## 4. 10주간의 여정 소감

이번 10주간은 단순한 코드 작성이 아니라, **7년 만에 다시 개발 프로젝트에 참여한 특별한 경험**이었습니다.  
오랜만에 코드를 작성하다 보니 초기에는 많이 버겁기도 했지만, 그만큼 더 깊이 몰입하며 학습하고 성장할 수 있었습니다.

특히 **대규모 트래픽을 견딜 수 있는 시스템 설계**를 직접 경험한 것이 가장 큰 성과였습니다.  
락 경합, Kafka 메시지 유실, DB 커넥션 풀 고갈 등 실제 서비스에서 충분히 발생할 수 있는 문제들을  
직접 마주하고 해결하면서, 우리가 매일 사용하는 서비스들이 어떤 아키텍처로 구성되어 있는지 궁금해졌고  
더 많이 찾아보고 공부하는 계기가 되었습니다.

또한 IT기획자로서 개발자들의 업무 방식과 사고방식을 체감할 수 있었던 소중한 시간이었습니다.  
앞으로 개발자들과 **더 효과적으로 소통할 수 있는 IT기획자**,  
그리고 때로는 개발 관점에서 더 날카로운 질문을 던질 수 있는 기획자가 되고 싶습니다.

이 프로젝트를 통해 얻은 경험은 단순한 개발 역량을 넘어  
**시스템 설계, 문제 해결, 협업 능력**까지 성장시켜 주었고,  
앞으로의 커리어에서 큰 자산이 될 것이라고 생각합니다.
